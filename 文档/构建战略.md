# 章程构建战略

> 不按目录施工。目录是阅读顺序，战略是施工顺序。

---

## 一、起点：这套章程是长出来的

编号里有证据。

```
第一条之一   第六条之二～之七   第十二条之二、之三   第三十一条之二、之三
```

「之 X」是插入式补丁——当时发现漏了一条，又不能动后面所有编号，于是插进去。严谨版里这类补丁有 16 处（章程 15、规则 1）。

这意味着两件事：

1. **现有条文不是按施工顺序排列的**。补丁的位置记录的是「当时发现漏了什么」，不是「这件事本该第几步做」。
2. **拆解不是重新分类，是还原工序**。把补丁放回它本该在的阶段。

---

## 二、四个地基决策

这四件事不定，写多少条都是空转。它们不是条文，是条文的前提。

| # | 决策 | 必须回答 | 现有锚点 | 定错的后果 |
|---|---|---|---|---|
| 1 | **权力归谁** | 最高权力机关是全会还是常设机构？常设机构有没有行政权？ | 第十三条、第二十二条 | 要么全会架空，要么常任委一言堂 |
| 2 | **成员边界** | 在校/校友/校外怎么划？谁有投票权？特殊身份算什么？ | 第七条、第八条、第十二条之二 | 选举时不知道谁有票，结果随时可被质疑 |
| 3 | **决策门槛** | 什么事三分之二？什么事过半？两次表决怎么算？ | 事项分类规则第一～四条 | 每次表决现场吵规则 |
| 4 | **争议终局** | 谁解释章程？谁裁机构间争议？申诉到哪一级为止？ | 第六条之二、第四十五条 | 出现争议无终局，组织直接分裂 |

**第一周不该写条文，该把这四个问题吵完。** 每个决策写成一页「决策单」，记下：结论、理由、被否决的方案、否决理由。这四页纸是后面所有条文的引用源。

## 三、七个施工阶段

### P0 立主体

| 项 | 内容 |
|---|---|
| 要回答 | 我们是谁、章程管到哪、下位文件能不能越过它 |
| 条文 | 第一条—第六条之七 |
| 前置 | 无 |
| 验收 | 一个外人读完，能一句话说清这是什么组织、章程的边界在哪 |
| 跳过的代价 | 后面每一条都可以被质疑「凭什么」 |

### P1 立成员

| 项 | 内容 |
|---|---|
| 要回答 | 谁能进来、进来有什么权利、怎么退出、创始人算什么 |
| 条文 | 第七条—第十二条之三 |
| 前置 | P0 |
| 验收 | 给出任意一个人的三种属性（在校/校友/校外 × 是否特殊身份 × 是否创始人），能唯一判定其身份类别与权利集 |
| 跳过的代价 | 没有「谁」，后面的「谁表决」「谁被选举」全部悬空 |

### P2 立决策

| 项 | 内容 |
|---|---|
| 要回答 | 权力归谁、怎么开会、什么事走什么门槛、民主与集中怎么衔接 |
| 条文 | 第一条之一、第十三条—第二十一条、事项分类规则第一～七条 |
| 前置 | P1（没有成员就没有表决主体） |
| 验收 | 给出任意一个议题，能唯一判定：谁提、谁审、几次表决、各需多少票 |
| 跳过的代价 | 组织能成立，但做不出任何有合法性的决定 |

> **这是分水岭。** P0–P2 完成，组织「能开会」；P3–P5 完成，组织「能运转」。

### P3 立执行

| 项 | 内容 |
|---|---|
| 要回答 | 谁来干活、每个机构管什么、职权边界在哪、机构之间什么关系 |
| 条文 | 第二十二条—第二十七条、第三十二条—第四十条 |
| 前置 | P2 |
| 验收 | 把现有全部事务列一遍，每项都能找到唯一主管机构，且不重叠、不留空白 |
| 跳过的代价 | 决议无人执行 |

### P4 立监督

| 项 | 内容 |
|---|---|
| 要回答 | 谁监督程序合法性、谁调查、谁审判、三权怎么分开 |
| 条文 | 第二十八条—第三十一条之三 |
| 前置 | P2（需要先有「合法程序」的定义） |
| 验收 | 任意一个机构决定，都能指出它违反了哪条程序、由谁受理 |
| 跳过的代价 | 机构一旦建起来就会抵制监督，后期再补要付双倍成本 |

> **P4 不能排在 P3 之后。** 顺序应该是「先造笼子，再造老虎」，至少同时。现有章程把监督机构放在第六章、执行机构在第四章，是**阅读顺序**，不是施工顺序。

### P5 立救济

| 项 | 内容 |
|---|---|
| 要回答 | 不服决定找谁、几级终局、外部争议怎么处理 |
| 条文 | 第四十五条—第四十九条 |
| 前置 | P3 + P4（要有决定、要有审判机构） |
| 验收 | 任取一个已作出的决定，能画出完整的申诉路径，并指出终点 |
| 跳过的代价 | 有监督无救济，监督变成另一种压制 |

### P6 立处罚

| 项 | 内容 |
|---|---|
| 要回答 | 什么行为对应什么后果、谁认定、谁决定、怎么申诉 |
| 条文 | 处罚规则第一～十七条 |
| 前置 | P1 + P2 + P5（成员定义、表决门槛、申诉路径全部就位） |
| 验收 | 任取一个违规行为，能唯一匹配到：定性、处罚类型、决定机构、申诉机构、时限 |
| 跳过的代价 | 处罚清单写得再细也执行不了，因为「谁有权罚」还没定 |

> **处罚必须最后写。** 它是整套机制的末端执行器，前面任何一环缺失，处罚规则就会变成一张无法落地的清单。现有 20 条处罚规则全部填了章程依据，共引用 18 个不同条文、29 次——这些依据必须先成立。
>
> 而且它已经出过事：**20 条里有 10 条引用了不存在的条号**（第五十五、五十九、六十七、六十八、七十一、八十三、八十八、八十九、九十二条）。这是章程重排编号后留下的悬空引用。处罚规则先于依据定型，就会变成这个样子。

### P7 立对外与安全

| 项 | 内容 |
|---|---|
| 要回答 | 谁能代表组织对外、活动安全谁负责、数据怎么处理 |
| 条文 | 第四十一条—第四十四条、第五十条—第五十四条、对外文书 |
| 前置 | P0 + P3（要有主体资格、要有代表机构） |
| 验收 | 一次对外活动，从立项到结束，每个环节都能找到责任主体 |
| 跳过的代价 | 出事时找不到责任人 |

## 四、依赖关系

```
P0 ──→ P1 ──→ P2 ──┬──→ P3 ──┬──→ P5 ──→ P6
                    │         │
                    └──→ P4 ──┘
                              │
P0 ───────────────────────────┴──→ P7
```

三条硬约束：

1. **P4 与 P3 同时或更早**——监督机构不能等执行机构建完再建。
2. **P6 必须在 P5 之后**——没有申诉路径的处罚是无效处罚。
3. **P2 之前不写任何机构条文**——否则机构会按自己的方便倒推决策规则。

可并行：P3 与 P4 可同时推进；P7 只要 P0 完成就可以独立开工。

## 五、最小可运转版本

如果只能先写 15 条，让组织跑起来：

| 序 | 条文 | 作用 |
|---|---|---|
| 1–3 | 第一条、第二条、第五条 | 主体、宗旨、章程效力 |
| 4–6 | 第七条、第八条、第九条 | 成员类别、权利、义务 |
| 7 | 第一条之一 | 民主集中制（决策的总原则） |
| 8–9 | 第十三条、第十四条 | 全会是最高权力机构、职权来源 |
| 10 | 第二十二条 | 常任委员会（闭会期间的常设机构） |
| 11–13 | 事项分类规则第一～三条 | 重大/大型/普通事项的门槛 |
| 14 | 第二十八条 | 三机构设立与独立 |
| 15 | 第四十五条 | 申诉权 |

这 15 条能支撑：开会、表决、选出机构、对决定不服时有地方去。**其余 157 条都是在这 15 条上长出来的。**

## 六、施工方法（比顺序更重要）

每个阶段按同一套动作走，不要跳步：

1. **写决策单**（一页）：结论、理由、被否决方案、否决理由。
2. **冻结决策单**：这一阶段内不再改，改了要记录变更理由。
3. **展开成条文**：一条只写一件事；需要引用别条时用哈希，不用编号。
4. **写验收案例**：拿三个真实场景跑一遍，跑不通就回去改条文。
5. **打阶段标签**：`stage/P0` … `stage/P7`，让后来人能看出哪一批是一起定的。

第 4 步是最容易被省掉、也最容易出事的一步。条文写得漂亮但跑不通案例，等于没写。

## 七、三个治理风险

| 风险 | 表现 | 对策 |
|---|---|---|
| **编号漂移** | 插入条文导致后续编号全变，历史引用失效 | 引用一律用内容哈希（`#84009d08`），编号只作展示 |
| **双版本不同步** | 严谨版改了，通俗版没跟上 | 同哈希必须双版本对齐，`query.py` 可按哈希核对 |
| **规则越权** | 下位规则创设了章程没授予的职权 | 每次规则修订，逐条比对章程职权清单 |

> 上表第一行不是假想风险。处罚规则 20 条里有 10 条正引用着已经不存在的条号——这就是编号漂移真实发生过的痕迹。

---

## 八、一句话总结

**先定四个决策，再按 P0→P7 施工；P4 不能晚于 P3，P6 必须最后；每阶段先写决策单再写条文，写完立刻用案例验收。**
